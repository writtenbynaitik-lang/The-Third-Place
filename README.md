# The Third Place — website concept

A speculative website for **The Third Place**, a coffee house and wine bar on the
first floor of Jewel Tower, Lane 5, Koregaon Park, Pune.

> **Unofficial.** Produced independently as a design proposal. Not commissioned,
> reviewed or endorsed by the restaurant. The restaurant was not contacted.
> **Not deployed, and not to be deployed without the owners' permission** —
> the photography is theirs. See [`assets/ASSET-MANIFEST.md`](assets/ASSET-MANIFEST.md).

---

## Quick start

```bash
npm install
npm run images
npm run build
npm run preview
```

Then open **http://localhost:5181**.

`npm run images` takes about five minutes the first time (186 derivatives from 19
originals) and is incremental afterwards — it only writes files that do not exist.
`npm run build` needs `assets/image-data.json`, which that step produces, so run it
once before the first build.

### Scripts

| Command | What it does |
|---|---|
| `npm run images` | Build responsive AVIF/WebP/JPEG derivatives + `image-data.json`. Add `-- --force` to rebuild everything. |
| `npm run dev` | Dev build + server on **http://localhost:5180**, serving `src/` unbundled for fast iteration. |
| `npm run build` | Production build → `./index.html` and `./dist/`. |
| `npm run preview` | Serve `dist/` on **http://localhost:5181**. |
| `npm start` | `build` then `preview`. |

Ports 5180/5181 were chosen because 4173 was occupied on the development machine.
To change one, edit `package.json` or run `node tools/serve.js dist <port>`
directly. The server refuses to start quietly on a busy port.

Node 20+ (developed on 24.21). Two dev dependencies: `sharp` and `esbuild`.
Nothing is fetched at runtime — fonts are self-hosted and there is no CDN.

## What this is

The Third Place has no website. Its whole online presence is an **unclaimed**
Zomato listing that gets its cuisine wrong in all four tags, a District booking
page under twenty-five bank-card offers, and an Instagram bio truncated at
"Open daily, 12:00 pm…". Google still offers "Add website" on its profile.

Meanwhile the restaurant itself is carefully made: a properly typeset menu with a
real mark and a real voice, a room designed around daylight and salvage, and a
wine list that champions Nandi Hills and Nashik alongside Chablis.

**The gap between the two is the project.**

### The concept — "Home. Work. And here."

The name is a real idea, not decoration. Ray Oldenburg's *third place* is the
public room between home and work; the founder says it outright. And the brand
mark is literally three strokes: `| | |`.

So the site is built on three, and on one other verified fact — the hours. Open at
noon, closing at 11:30. **One room that is a coffee house by day and a wine bar by
night.** The page performs that: it begins in daylight on cream paper and ends
after dark in lacquer red and lamplight. Scrolling it is the arc of a day in the
room.

The signature interaction follows from the same idea. The hero photograph is cut
into vertical slats that rotate on their own axis as you scroll. Face-on they are
one continuous photograph of the room; turned, they resolve into a rhythm of
vertical strokes — the mark — and their reverse faces carry the same room in
evening light. The mark *is* the room, seen edge-on; day becomes night by turning.

Full reasoning in [`project-brief.md`](project-brief.md).

## Project structure

```
index.html              generated by the build — do not edit
src/
  index.html            the template (edit this)
  css/                  tokens · base · components · header · hero · sections · reveal
  js/
    main.js             entry: ordered, independently guarded init steps
    nav.js              header state, drawer, scroll-spy
    menu.js             menu rendering + WAI-ARIA tab list
    menu-data.js        the verified menu (and the price switch)
    hours.js            opening hours + live open/closed, Asia/Kolkata
    reveal.js           scroll reveal
    hero-slats.js       the WebGL hero — dynamically imported, ~7 kB, no framework
tools/
  assets.config.js      one entry per image: source, role, focus, alt, widths
  images.js             the image pipeline
  build.js              template expansion + bundling
  serve.js              static server with path-traversal protection
assets/                 originals, derivatives, fonts, brand
dist/                   production output
```

## Editing content

**Menu.** `src/js/menu-data.js`. Dish names and descriptions are transcribed from
the restaurant's printed menu. `marks` reproduces only the symbols actually printed
beside a dish — the menu's own allergen key and its red non-vegetarian square. No
dietary claim is added anywhere.

**Prices** are transcribed but hidden, because the menu scans carry no date and
currency could not be confirmed. To publish them:

```js
// src/js/menu-data.js
export const showPrices = true;
```

**Hours.** `src/js/hours.js` drives the live open/closed line. The static table in
`src/index.html` and the JSON-LD must be changed to match — three places, by design,
so no single edit can leave the page half-right.

**Photography.** Drop a file into `assets/originals/`, point the entry in
`tools/assets.config.js` at it, adjust `focus` and `alt`, then
`npm run images && npm run build`. No filename, width or ratio is hardcoded in the
markup.

## Principles the code holds to

**Nothing is invented.** Every fact traces to a line in `research/RESEARCH.md`.
Where sources disagreed — cuisine, hours, the pizza line-up — the disagreement is
documented along with which source won and why. No ratings, reviews, offers,
awards, customer counts or dietary claims appear, even though several were
available.

**Nothing pretends to work.** No booking form, no order flow, no email capture, no
contact form. Booking goes to District in a new tab and the page says so. There is
no email address anywhere, because none exists in any source.

**Every link goes somewhere real.** 37 links, zero placeholders, five external
destinations, each one opened and confirmed.

**The page degrades honestly.** It was tested with WebGL disabled, JavaScript
disabled, every image 404ing, and reduced motion — each as a separate harness over
HTTP, not as a thought experiment. The `.reveal` class is applied by JavaScript at
runtime specifically so that a JavaScript failure cannot leave content invisible.

**The spectacle is optional and cheap.** The WebGL hero is a dynamically-imported
7 kB module — no Three.js for three textured quads. It never initialises under
reduced motion, on a data saver, on fewer than four cores, or without WebGL; it
stops rendering when offscreen or hidden; the device pixel ratio is capped at 2;
and the static photograph underneath is both the LCP element and the permanent
fallback. The pause control is only created once there is something to pause.

Measured on a cold cache: **343 kB, 8 requests, CLS 0.**

## Before this could go live

1. Confirm hours, and whether breakfast is still served.
2. Confirm the menu prices are current, then flip `showPrices`.
3. Confirm the current pizza line-up — the launch press and the menu scan disagree.
4. Replace the photography with owner-supplied originals, or obtain permission.
5. Get the official logo artwork and confirm the wordmark typeface.
6. Set a canonical URL, an absolute `og:image`, and a real favicon set.
7. Decide whether "Saturday Muse", "Wed Theatre" and "D'canted Wine" deserve a section.
8. Test on real devices and with a screen reader.

Items 1–5 and 7 are expanded as open questions A–H in `research/RESEARCH.md`.
